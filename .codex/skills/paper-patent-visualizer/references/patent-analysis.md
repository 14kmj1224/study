# Patent analysis mode

Use the granted or published patent PDF as the primary source. Treat the abstract and summary as orientation, the detailed description as embodiments, and the claims as the legal boundary expressed by the document.

## Required analysis

1. Capture bibliographic facts visible in the PDF: publication or patent number, title, applicant or assignee, inventor, dates, family relationship, and classifications.
2. State the prior technical problem without adopting promotional language.
3. Reconstruct the disclosed mechanism in functional order.
4. Map every independent claim into essential elements using concise paraphrases. Keep dependent-claim additions separate.
5. Distinguish required claim elements, optional embodiment details, experimental conditions, and analyst interpretation.
6. Evaluate evidence, implementation constraints, likely failure modes, and missing validation.

## Claim map fields

- Claim number
- Claim type: method, apparatus, system, composition, or other
- Essential element
- Technical role
- Supporting description or figure
- Scope note

Never infer infringement, validity, enforceability, or freedom to operate. If the PDF is a divisional or continuation, report that relationship but do not infer the status of related cases without verification.
